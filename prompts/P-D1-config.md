> 用在 D1（动作 1，新会话）；使用者：干活 agent（新开会话，不与计划会话混用）。来源：主手册 v0.9，逐字抽取，`[...]` 为要你自己换的占位。

读 docs/intake-checklist.md，陪我逐项配置。规则：
1. 一次只做一项，告诉我具体去哪里点什么。
2. 每配完一项，明确告诉我需要把密钥同步填入哪几处（本地 .env.local、云服务器 worker 环境、Vercel Preview 环境变量、GitHub Actions CI Secrets）。
3. 我说"完成"后，你用不依赖项目代码的最小真实调用来验证凭据有效（例如调一次 API 健康接口、查余额/配额、验证 DNS/Webhook 连通）。通过才把状态改为"已验证"；失败就帮我诊断。
4. 密钥只放进 .env.local 及平台环境变量，确认 .env.local 在 .gitignore 里，不要写进任何会提交的文件或日志。
5. 不配置生产/不可逆操作密钥。Supabase 访问令牌、数据库密码只放 GitHub Environment db-admin；不给 worker。主网私钥不进入自动环境，也不设 ALLOW_MAINNET。
6. 所有付费或按量计费的服务（托管平台、数据库、大模型 API、邮件服务等），配好账号后第一时间设置月度预算上限或告警，并告诉我：到了上限是只通知还是会真的停用。
7. 在浏览器把仓库导入 Vercel，手动选 Next.js 预设，生产分支先设为一个暂不存在的分支（例如 production；这个分支名要在 D2 用 `production-lock` 锁住，否则有写权限的账号误建它可能触发生产部署），核对已有部署记录（空仓库部署失败也可，见 3.6）。外部回调先记 integration 的稳定预览域名和验签路径，放行与真实投递留到 E3 的最小真实链路。
