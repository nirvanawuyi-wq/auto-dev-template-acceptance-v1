> 用在 C2（动作 1）；使用者：干活 agent（主会话）。来源：主手册 v0.9，逐字抽取，`[...]` 为要你自己换的占位。

读 docs/requirements.md、docs/questionnaire.md 和 docs/workflow-manual.md，写第一轮计划草案 docs/plan-draft.md。其中板块 0 的工程护栏（分支与合并、CI 守卫、受保护路径、验收测试锁定、密钥分层）以手册附录 B 为准，不要另起炉灶，也不要添加附录 B.8 列为"暂不做"的东西。草案包含：
1. 技术方案：每个外部服务选哪个、为什么、有什么替代。
2. 板块划分：每个板块写范围、验收标准、不许碰的目录和文件。
3. 板块 0（地基）产出：项目骨架、核心依赖预装、共享类型/数据契约、数据库迁移与类型文件（由你从 main 手动触发 migrate.yml，填入确认过的提交号，附录 B.5）、.env.example 与环境变量启动校验、复制 .env.local 的 .ai/bin/setup-worktree.sh、默认走 Mock/沙箱桩的 CI（前端只检基础可用性）、中性主题变量（语义化 token + --font-heading 插座）和保底版 DESIGN.md（3.8）、仅非生产环境可见且加鉴权的极简 /debug（用 VERCEL_ENV 判断；读任务记录表，展示编号、时间、状态、简短原因，不存原文或完整入参）、根目录 AGENTS.md 与各工具所需的兼容文件（3.1），以及附录 B 的受保护路径、pnpm verify、ESLint 零豁免、CI、锁定的验收测试、按板块拆分的交付开关和数据库体检。再做一条"最小真实链路样板"（例如：测试邮箱发来照片 → 入库 → 预览可见，刷新后仍在）。
4. 板块之间交接的数据格式。
5. 共用资源（数据库迁移、共享配置、外部测试账号等）分别归哪个板块使用。
6. 预计需要我提前配置的外部服务，以及每个密钥要放的位置（本机 .env.local / 服务器环境文件 / Vercel Preview / GitHub Secrets，按附录 B.7）。测试和生产必须各用独立项目（数据库、存储等）。
7. 技术选型问卷：看完这份技术方案后才会出现的新决策点（外部服务取舍、账号域名归属、配额与测试隔离方案等），列成问卷，每题带推荐答案。
