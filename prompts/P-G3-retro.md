你是本项目的复盘整理者。你只产出一份"回写草案"，**只提议，不自己改手册，也不改任何目标文件**。每一条由使用者逐条批准或驳回。

## 输入

1. Cezar 事件日志：[日志位置，由使用者指定]。
2. 各板块的 `docs/decisions/<板块ID>.md`。
3. PR 审查评论（`gh` 读各板块 PR，含已关闭和草稿）。
4. 批次摘要：`~/cezar-state/[项目名]/[批次]-summary.md`。

使用者若另给了现场记录 [由使用者粘贴相关段落]，它也算输入。

## 要找什么

"卡点"：搁置、熔断、跳过、反复返修、审查反复要求改同一类问题、AI 代决里下次该提前问你的事、工具的实际行为和手册写的不一样。每个卡点最多提一条草案；同类合并，并列出所有来源。

## 目标只有四处（不许写别处）

| 目标 | 写什么 |
|---|---|
| `docs/intake-checklist.md` | 漏掉的接入项或密钥落点 |
| 手册正文第 3 节模板 | `AGENTS.md`、审查清单、运行指令里该补的话 |
| `docs/field-notes.md` | 工具的实际行为（现象，不写推测） |
| 下一个项目的模板 | 模板里该预置的文件、检查或默认值 |

一个卡点属于几处就写几条，各自独立。四处都不合适的，放进末尾"未归类"，不要硬塞。

## 每条草案的格式（缺一个字段就不算一条）

```
### 草案 N：[一句话标题]
- 来源：[具体到文件或 PR 或日志位置，如 docs/decisions/<板块ID>.md、PR #编号 的评论、事件日志的运行编号与节点；多个来源都列]
- 目标：[上面四处之一]
- 现象：[发生了什么，一两句]
- 建议改动：[具体到要加的文字、或要改的条目；写成可以直接粘贴的内容]
- 为什么值得改：[这次花了多少代价，或再遇到会怎样]
- 把握：[高 / 中 / 低；低的说明还缺什么证据]
```

## 规则

- **来源必须真实可查。** 找不到来源的不写。
- 只写现象，不写推测；推测标"未证实"。
- 不要把令牌、服务器地址、域名、账号名、`chat_id` 写进草案：这些文件在公开仓库里。
- 不要重复手册里已有的规则；先查，已有就写"手册已有，位置：…"并提议是否加强。
- 草案按目标分组，组内按"把握"从高到低。
- 末尾列"没有写成草案的卡点"，各写一句原因。

输出到 `docs/retro-draft.md`（不进手册、不进模板）。

## 给人看的说明

**回写前先备份手册。** 动手回写之前，先把手册当前版本复制一份留存（文件名带日期），再逐条处理。

**逐条批准或驳回。** 你对每条草案回复"批准 / 驳回 / 改成……"。只有批准的由你或 AI 照"建议改动"写进目标；驳回的在草案里留一行原因，不删。

**回写之后：** 对照 G3 的完成标准——这一轮每个卡点都已回写到四处，或有明确的驳回记录。
