# 返修入口：说一句问题，到复验通过

**一句话：** 你只说问题，其余五步照下面走；每个问题一个返修分支，修好后用同一个操作复验。

## 流程

1. **你说一句问题。** 大白话，说哪里不对即可。
2. **整理成四项。** 让 AI 用提示词 `P-F2-fix` 把它整理成：
   - 板块
   - 操作（你做了什么）
   - 看到什么
   - 期望什么

   后台流程有卡点时，附上 `/debug` 里按编号查到的时间、状态和简短原因。
3. **提交返修任务。** 填入第 2 步的四项内容及可运行的检查命令和预期结果。目标分支为 `integration`，任务分支为 `fix/<板块ID>-<序号>`。保持原板块 ID，从未占用的序号里取下一个。
4. **记下任务编号。** 接单后，把返回的运行编号记入返修记录。PR 出现后补上 PR 编号。
5. **等返修 PR 合入 `integration`。** 板块之间的合并规则按手册；你不用自己合。
6. **用同一个操作复验。** 在 `integration` 的预览上，重做第 2 步里写的那个"操作"，对照"期望"。通过就记下；不通过，回第 1 步，序号加一。

## 云端执行器入口

在 Cezar 驾驶舱选当前项目的 `module-delivery`，填入第 3 步的任务内容。走提交脚本时沿用 D3 核对过的入口和参数。在驾驶舱用运行编号查进度。

## 规则

- 一个问题一个分支一个任务。别把几个问题塞进一条。
- 板块拿不准时，先问 AI 是哪个板块，别猜。
- 复验用的操作要和第 2 步完全一样，不要换一个更容易过的。
- 返修记录别写令牌、服务器地址、账号名。

## 填好的示例（虚构的猫咪相册项目）

**你说：** "照片上传完，预览页上猫的照片比例怪怪的，被压扁了。"

**整理后的问题条目：**

| 项 | 内容 |
|---|---|
| 板块 | `photo-upload` |
| 操作 | 在相册页上传一张竖版手机照片，上传成功后点进预览页 |
| 看到什么 | 预览页的照片被横向拉宽，猫脸变扁。`/debug` 里该上传任务的状态是"已完成" |
| 期望什么 | 预览页按原比例显示，竖版照片不被拉伸 |

**提交信息：**

- 任务：`module-delivery`
- `base=integration`
- 分支：`fix/photo-upload-1`
- 任务编号：`[提交后由驾驶舱或提交脚本给出，抄在这里]`

**返修记录（边做边填）：**

| 项 | 内容 |
|---|---|
| 任务编号 | `[...]` |
| 返修 PR | `[...]` |
| 合入 `integration` | `[是 / 否，时间]` |
| 复验操作 | 同上：上传同一张竖版照片，点进预览页 |
| 复验结果 | `[通过 / 不通过，看到什么]` |
